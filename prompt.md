# Build Brief — Personal Portfolio Website

You are building my personal developer portfolio from scratch.

I will provide:

* My professional photo
* My resume as a `.md` file
* Design/frontend skills or agent skills available in the environment
* A reference website: https://landonorris.com/

Your job is **not to reproduce the reference website**.

Use it as inspiration for the level of polish, visual storytelling, interaction quality, and motion design — but create a completely original visual identity and experience around **me as a software engineer/developer**.

## 1. Core objective

Create a portfolio that feels like a **designed digital experience**, not a generated developer template.

When someone opens it, the immediate impression should be:

> "This person actually cares about software, design, interaction, and details."

It should feel:

* modern
* highly intentional
* technically impressive
* smooth
* editorial
* slightly experimental
* personal
* memorable
* professional enough for recruiters and engineers

Do NOT make it look like:

* a generic SaaS landing page
* a typical developer portfolio
* a Tailwind template
* a "vibe-coded" AI website
* a Dribbble clone
* a portfolio with random gradients and glassmorphism
* a page containing excessive cards with rounded corners
* a collection of meaningless animations

## 2. Design direction

Start by developing a **visual concept** before writing the UI.

The design should have a recognizable identity of its own.

Do not automatically default to:

* purple/blue gradients
* black background + neon green
* excessive blur
* glass cards
* glowing borders
* floating blobs
* huge gradient text
* animated grid backgrounds
* excessive rounded rectangles

If an accent color is used, it should have a reason.

Think more in terms of:

**art direction + typography + composition + photography + motion**

rather than:

**components + cards + gradients**

The visual language should feel closer to a premium creative studio / product designer / experimental technology site than a conventional developer portfolio.

## 3. Use my actual identity

Read my resume carefully.

Do not invent:

* jobs
* companies
* projects
* technologies
* achievements
* metrics
* education
* experience
* skills

Everything factual must come from the supplied resume.

However, you CAN transform factual information into stronger visual storytelling.

For example, instead of simply:

"Skills: C++, React, Node.js"

create a more interesting presentation of the same information.

The website should communicate who I am professionally without becoming a wall of resume text.

## 4. Hero section

The hero should be the strongest part of the website.

Use my supplied photo intelligently.

Do NOT simply put:

[photo]
"Hi, I'm Santhosh"
"Software Developer"
[button]

That is too generic.

Instead, create a visually distinctive introduction where:

* typography has strong hierarchy
* the photograph is integrated into the composition
* the viewport feels intentional
* there is subtle movement
* elements respond naturally to pointer movement where appropriate
* the page immediately establishes the site's visual language

Consider experimental techniques such as:

* image masking
* layered typography
* kinetic typography
* image displacement
* subtle parallax
* cursor interaction
* typography/image overlap
* progressive reveals
* scroll-linked movement

But only use techniques that improve the experience.

## 5. Motion philosophy

Animation is important, but **animation should communicate hierarchy and physics**, not exist just because an animation library was installed.

Use motion throughout the site.

Examples:

### Page entrance

A carefully choreographed initial reveal rather than everything fading in simultaneously.

### Typography

Text can reveal line-by-line, word-by-word, or through clipping/masking.

### Images

Images can reveal through masks, subtle scale changes, or directional movement.

### Scrolling

Sections should have meaningful transitions as the user moves through the page.

### Hover

Interactive elements should react with subtle but satisfying feedback.

### Navigation

Navigation should feel like part of the experience rather than a standard navbar.

### Cursor

A custom cursor can be used if it genuinely improves the experience.

Avoid:

* excessive bouncing
* random floating elements
* animation on every element
* slow animations that make the website frustrating
* animations that interfere with reading
* fake "3D" effects everywhere

The motion should feel **fast, physical, deliberate and premium**.

## 6. Performance is a design requirement

Do not sacrifice usability for visual effects.

The website must:

* load quickly
* remain responsive
* maintain smooth scrolling
* avoid unnecessary re-renders
* lazy-load heavy media
* optimize images
* respect reduced-motion preferences
* work well on lower-end hardware

If WebGL, shaders, R3F, GSAP, Lenis, Framer Motion, or similar technologies are used, use them deliberately.

Do not add libraries simply because they are fashionable.

## 7. Portfolio structure

Create a strong narrative rather than a collection of unrelated sections.

Possible structure:

1. Hero / Introduction
2. Selected work
3. About / approach
4. Experience
5. Technical capabilities
6. More work / experiments
7. Personal dimension
8. Contact / closing statement

However, **do not blindly follow this structure**.

Let the resume and projects determine the final information architecture.

The sections should feel like parts of one continuous experience.

## 8. Projects

Projects are extremely important.

Do not display them as generic:

┌──────────────┐
│ Project Img  │
│              │
│ Project Name │
│ Description  │
│ [GitHub]     │
└──────────────┘

Instead, create a project presentation system with personality.

Projects could use:

* large editorial layouts
* asymmetric compositions
* horizontal scrolling where appropriate
* image/video previews
* project-specific color accents
* interactive previews
* hover transformations
* sticky storytelling
* large typography
* technical details revealed progressively

Each project should answer:

**What did I build?**
**Why did I build it?**
**What was technically interesting?**
**What was my contribution?**
**What was the result?**

But keep the initial presentation visually concise.

## 9. Resume integration

Treat the resume as the source of truth.

Extract:

* experience
* education
* projects
* technical skills
* achievements
* links
* relevant personal/professional information

Do not dump the resume onto the website.

Instead, convert the information into an interactive narrative.

The website should make the resume feel more compelling than simply opening the `.md` file.

Include an obvious way to access/download the full resume.

## 10. Typography

Typography should be a major part of the design.

Use a carefully selected font pairing.

Consider:

* one strong display typeface
* one highly readable body/UI typeface
* possibly a mono font for technical metadata

Typography should create hierarchy through:

* scale
* weight
* spacing
* position
* movement

Do not use five different fonts.

Do not use oversized text everywhere just to make it look "modern."

## 11. Layout

Avoid repetitive card grids.

Use:

* asymmetric layouts
* intentional whitespace
* full-bleed sections
* overlapping elements
* editorial compositions
* changing section rhythms
* sticky elements
* large visual moments

The page should have moments of tension and release.

Not every section needs the same layout.

## 12. Interaction design

Use interaction as storytelling.

Examples:

A project could subtly transform as the cursor moves over it.

A skill could be revealed through interaction rather than a list of badges.

A timeline could become an interactive visual narrative.

The photo could respond subtly to pointer movement.

Navigation could transition between sections rather than simply jumping.

But always ask:

> Does this interaction make the content more understandable or memorable?

If not, remove it.

## 13. Reference website analysis

Study https://landonorris.com/ for:

* visual pacing
* art direction
* typography scale
* photography treatment
* section transitions
* scroll choreography
* interaction patterns
* image composition
* storytelling
* use of whitespace
* relationship between static content and motion

Do NOT copy:

* its exact layouts
* colors
* graphics
* text
* navigation
* visual assets
* animations
* branding
* composition

We want the **design principles**, not a clone.

## 14. Responsive design

Do not treat mobile as an afterthought.

Design mobile independently where necessary.

The experience should remain excellent on:

* desktop
* laptop
* tablet
* mobile

On mobile:

* simplify interactions when necessary
* remove expensive effects where appropriate
* preserve the visual identity
* maintain excellent typography
* ensure touch targets are comfortable
* never require hover interactions

## 15. Accessibility

Implement proper:

* semantic HTML
* keyboard navigation
* focus states
* contrast
* alt text
* reduced motion support
* accessible buttons/links
* screen-reader-friendly structure

Accessibility should not be added at the end.

## 16. Technical quality

Use a modern frontend architecture.

Prefer:

* clean component boundaries
* reusable animation utilities
* centralized design tokens
* semantic naming
* minimal unnecessary dependencies
* maintainable code
* responsive CSS
* optimized assets

Keep the implementation understandable.

Do not generate one giant component containing the entire website.

Do not create unnecessary abstractions simply to make the code look sophisticated.

## 17. Design-system thinking

Before implementing the full site, establish:

* color system
* typography system
* spacing scale
* motion principles
* border/radius philosophy
* interaction states
* image treatment
* grid/layout system

The site should feel like one coherent product.

## 18. Important anti-slop rules

These are hard constraints.

DO NOT:

* use generic purple-blue gradients
* use excessive glassmorphism
* use random glowing blobs
* use generic AI-generated copy
* use meaningless statistics
* use fake testimonials
* use fake client logos
* invent achievements
* use excessive rounded cards
* animate everything
* add a loading screen just for drama
* use stock photography when my photo/assets are provided
* add unnecessary 3D
* add a giant "Available for work" pill just because portfolio templates do
* create a fake terminal window as the hero
* create a generic "Frontend Developer | Full Stack Developer | AI Enthusiast" hero
* use excessive emoji
* make every section look like a SaaS landing page

If a design decision looks like something an AI portfolio generator would commonly produce, reconsider it.

## 19. Design review before implementation

Before writing the final implementation, reason through at least 2–3 distinct visual directions internally.

Choose the strongest one based on:

* my actual personality/profile
* my resume
* my photo
* the type of roles I am targeting
* memorability
* usability
* technical feasibility

Do not show me generic design alternatives unless necessary.

Commit to a strong art direction.

## 20. Iterative refinement

After the first implementation, critically review the result.

Ask:

* Does this look like a real designer made it?
* Does anything feel template-generated?
* Is there too much motion?
* Is there enough motion?
* Are the animations synchronized with the content?
* Is the typography interesting?
* Does the hero have a strong identity?
* Are the projects the visual focus?
* Does the site feel cohesive?
* Does anything look like a default Tailwind component?
* Does anything look unnecessarily complicated?
* Is the experience fast?

Then refine.

Do not stop at "the website works."

The goal is:

**the website should feel finished.**

## 21. Final standard

I would rather have:

**6 excellent sections**

than:

**15 mediocre sections.**

I would rather have:

**3 memorable interactions**

than:

**30 generic animations.**

I would rather have:

**a strong visual identity**

than:

**a technically impressive website with no personality.**

The final result should make someone remember the site after closing the browser.

Build the portfolio as if you were an award-winning digital product designer collaborating with a senior frontend engineer.

The goal is not to demonstrate how many technologies you can use.

The goal is to demonstrate **taste, engineering ability, personality, and attention to detail.**
